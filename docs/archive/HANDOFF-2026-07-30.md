  with ISIN in parentheses.
- **P29–P30 — ADR-L04's two open questions**: `over_apportioned` reported per-scope, and D6's
  `threshold_weight <= 0` guard rejected at import time.
- **P31–P32 — `RiskLevel` re-anchored.** The invented 5-member enum is **rejected**. It becomes the
  **ordinal 1–7 synthetic risk indicator scale** (UCITS KIID calls it SRRI, PRIIPs KID calls it SRI;
  both are 1–7, so the member set is identical and the choice of name needs no further decision), with
  **each step named**: 1 `VERY_CONSERVATIVE` Molto prudente · 2 `CONSERVATIVE` Prudente · 3 `MODERATE`
  Moderato · 4 `BALANCED` Bilanciato · 5 `GROWTH` Dinamico · 6 `HIGH_GROWTH` Molto dinamico ·
  7 `AGGRESSIVE` Aggressivo. Additive: all five existing member names survive, two are added.
  `demo/strategy.yaml:11`'s `BALANCED` maps to **4**, the midpoint.
  **The constraint that matters:** this codebase does not compute SRRI/SRI. The value is
  owner-declared and merely *expressed on* the regulatory scale — no field, docstring, ADR line or UI
  string may imply derivation. Surface: `"Profilo di rischio {n} su 7"` full, `"Rischio {n}/7"` short.
  An earlier gloss draft reading "dichiarato **dal gestore**" was **withdrawn**: it invents an actor
  that does not exist in a self-directed single-user product and breaks P17.
- **P33 — computed risk is a separate feature, out of V1.0**, written up at
  `docs/features-candidates/portfolio-risk-level.md` (new folder). The declared profile is an input
  the system restates; a computed level is arithmetic against it, and collapsing them would let a
  computed number overwrite a user declaration.

### 3.2 W1d-b — it-IT filters, and the decision that keeps ISINs safe

`ConditionKindSpec` gains **`numeric_bindings`** (required, `C-L05-3`): each condition kind
**declares** which message bindings are locale-formattable `Decimal`s. Nothing is inferred from a
binding's name or its stored value, which is what makes it impossible for a locale filter to corrupt an
ISIN-bearing instrument name. `adapters/duckdb/queries/it_locale.py` provides `format_number_it`,
`format_money_it` (`€107.586,33`, `-€3.240,00`) and `render_observation_it`, which re-renders a frozen
template over frozen bindings. Read-side only, per ADR-L03 §5.2. `assemble_rationale` takes an injected

untouched** — it pins structured bindings only.

**The trace-replay diff was reviewed before acceptance** (RFC-0010 §6.2 makes weakening it a stop
condition). It is **one line** — `numeric_bindings=frozenset()` added to a test fixture's constructor
because the spec gained a required field. It **neither extends nor weakens** the property. An agent
reported it as "EXTENDED"; that overstates the diff, and the value of that check is that its verdicts
are literal.

### 4.1 What delegation actually cost, and what to do differently

The wave ran as one Sonnet `orchestrator` with two named lane agents. All three lanes landed green and
the technical work was good. The orchestration had three recurring failures, and they are cheap to
prevent:

1. **Both lane worktrees were created at `a264462`** — the bare scaffold commit on `main`, predating
   W1c, the engines and World B. Both agents noticed and re-branched from `build/skeleton` themselves.
   **Verify the base with `git -C <worktree> log --oneline -1` before briefing an agent into it.** An
   agent that had not noticed would have built against a tree missing everything it needed.
2. **Reporting lagged reality.** Three consecutive reports described states that had already been
   superseded, and one produced a redundant order to an agent to fix a violation it had already fixed.
   **Read the tree as the last action before sending, not before composing.**
3. **Agents held work uncommitted.** Both lanes sat with substantial uncommitted work until pressed.
   `commit per deliverable` has to be restated at dispatch *and* enforced by checking, because an
   uncommitted worktree is lost work if the stream dies.

**A trap for the main thread, not the agents:** the Bash tool's cwd persists across calls. A `cd` into
a worktree for one verification makes every later `git rev-parse HEAD` read *that* worktree. This
session produced a confident, wrong claim that the main checkout was flipping branches, and a shutdown
request citing it. **Use absolute paths or `git -C` for every repo query.**
